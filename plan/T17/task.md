# T17. Windows app and renderer

A C# WinUI 3 shell with a `SwapChainPanel` surface, a D3D11 renderer and a DirectWrite atlas. The first step evaluates the interop library that gives C# access to Direct3D and DirectWrite (maintenance, coverage, allocation cost per frame) and records the pick in `toolchain.md`; the research evaluated none. Done when a shell is usable and the T3 benchmark runs on Windows.

Execution plan (split to fit the budget). C# lives in `windows/`; the core is reached only through the committed csbindgen bindings, compiled in by link.

- T17.1 Interop pick and the managed core: compare Vortice.Windows, TerraFX.Interop.Windows, Microsoft.Windows.CsWin32 and Silk.NET for Direct3D 11, DXGI, DirectWrite, TSF and UIA (maintenance from NuGet and GitHub releases, coverage, per-frame allocations, AOT and trimming, licence), recorded in `research.md` with sources and the pick in `toolchain.md`. `windows/Scull.Core`, a platform-neutral class library over `NativeMethods.g.cs`: `Terminal` (create, feed, resize, events and bell, frame update and view, read text), `SafeHandle` ownership so each handle is freed once, the ABI version checked at start-up, status codes mapped to exceptions, poisoning tracked as `TerminalSession.swift` does. `windows/Scull.Core.Tests` loads the real Rust library and covers each of those. `just windows-core-test`, and a CI job on Windows and macOS. Verify: `just check`, `just windows-core-test`, `dotnet build` with warnings as errors.
- T17.2 Renderer library, testable headless: `windows/Scull.Render` (`net10.0-windows`, no WinUI types) over CsWin32 (`NativeMethods.txt` lists only what it uses, `allowMarshaling: false`). A D3D11 device, hardware or WARP when asked; DirectWrite rasterises glyphs into a shelf-packed BGRA atlas texture with eviction, growth and a generation, as grayscale coverage and as colour glyphs (COLR layers composited on the CPU); instanced quads for cell backgrounds, glyphs, underline and strike decorations and the cursor, in per-row instance slots that a scroll only remaps and dirty rows refill, drawn from a `Scull.Core` frame view into any render target view (a swap chain's back buffer in T17.3, an offscreen texture in the tests). HLSL compiled at start-up with `D3DCompile`. No allocation per frame in the steady state (struct COM pointers, pooled instance arrays). Glyphs come from the cell's code point through the face and a short fallback list; not in this slice: shaping with ligatures and `IDWriteFontFallback`, combining marks, box drawing and Powerline sprites and image placements (T17.5). `windows/Scull.Render.Tests` (MSTest): a real `Scull.Core.Terminal` fed text and colours, rendered on WARP into an offscreen texture and read back (background colours at known cells, coverage where text is and none where blank, the cursor block, one atlas entry for a repeated glyph), and the packer's growth and eviction as pure logic, which also runs on macOS and Linux. The solution builds everywhere (`EnableWindowsTargeting`); the Direct3D tests run only on Windows and are skipped elsewhere. Verify: `just check`, `just windows-core-test` locally and on the three CI runners, warnings as errors.

- T17.9 Core terminal events in the Windows shell: `EventKind` knew only the bell and the child's exit, so titles, the working directory and OSC 52 were dropped. As `TerminalSession.drainEvents` does on macOS: a title (not an icon-only one) becomes the tab's header and, for the selected tab, the window's title; the working directory (OSC 7, a local `file://` URL) is kept on the pane and nothing more (macOS only stores it too); an OSC 52 write puts its UTF-8 text on the clipboard (other bytes are dropped); an OSC 52 read is denied, because it would hand the user's clipboard to whatever the shell runs.
  Execution plan: (1) `Scull.Core/Terminal.cs`: `EventKind` gains `Title`, `WorkingDirectory`, `ClipboardRead`, `ClipboardWrite` (and the other ABI kinds, which the shell ignores); `TerminalEvent` carries `Id`, `Detail` and `Text` (bytes read through `tt_term_event_text` right after the poll, since only the last polled event's text is readable, grown on `TT_FULL`); `Terminal.ClipboardDeny(id)`. (2) `Scull.Core/EventPolicy.cs`, pure: `TitleOf` (icon-only titles skipped), `PathOfUrl` (local `file://` URL to a path, the host must be empty or `localhost`), `ClipboardText` (strict UTF-8 or null). (3) `Scull.App`: `TerminalPane.Exited()` becomes `Drain()` returning the child's exit and keeping `Title`, `WorkingDirectory`, with `ClipboardWritten` and denied reads handled there; `TerminalWindow` sets the tab header (fallback `Terminal N`) and the window title (fallback `Scull`) and writes the clipboard through `DataPackage`. (4) Tests: `EventTests` feeds a real `Terminal` OSC 0, 1, 2, 7 and 52 write and read sequences and reads the events; `EventPolicyTests` for the pure helpers. Verify: `just check`, `just windows-core-test`, CI incl. `just windows-app`. Not touched: the pointer handlers (T17.8) and `Scull.Render` (T17.10).
