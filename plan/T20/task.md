# T20. Configuration, fonts and themes

A config file loaded and validated in the core, with font, colour scheme, scrollback and key binding settings, live reload, and a settings view on each platform. Done when a change applies without restart.

Execution plan (split to fit the budget):
- T20.1. `crates/scull-config` model: `Config` TOML types (font family and size, colour scheme with overrides, scrollback), defaults, built-in schemes, load with a size cap and `deny_unknown_fields`, errors that name the file, JSON Schema committed to `docs/config.schema.json` with a stale-schema test. Verify: unit tests for parsing, defaults, every validation error and caps.
- T20.2. Key bindings in `scull-config`: `[[keybind]]` chord parsing over `scull_input::{Key, Modifiers}`, an action enum, default bindings merged with the user's, caps and duplicate checks. Verify: parsing and rejection tests.
- T20.3. Editing and live reload in `scull-config`: `toml_edit` setter that validates before it writes and replaces the file atomically; `notify` watcher on the parent directory feeding a store with a generation counter and the last error (a bad edit keeps the last good settings). Verify: tests that edit a temp file and see the generation and values change, and a broken edit keep the old settings.
- T20.4. C ABI in `scull-ffi`: `tt_config` handle (`new`, `poll` into a sized `tt_config_view`, `set`, `free`) behind the wakeup callback only; bump the ABI minor; `just bindings`; extend the C test under ASan and TSan. Verify: Rust tests, `just c-abi-test`, `just bindings-check`.
- T20.5. macOS: new `ScullKit/Config.swift` wrapper and `Palette`/`TerminalView` reading it (font, colours, key bindings, scrollback for new terminals); live reload through the wakeup. Verify: `just macos`, `just macos-test`, and the `-ScullSnapshot` PNG before and after editing the file while the app runs.
- T20.6. macOS settings view: new SwiftUI `Settings` scene in new files (family, size, scheme, scrollback) that writes through `tt_config_set`. Verify: `just macos`, a snapshot after a change made through the view.
- T20.7. Windows settings view, reusing T20.1 to T20.4 unchanged. T17 has landed the WinUI app, so it is split to fit the budget:
  - T20.7.1. `windows/Scull.Core/Config.cs`: `Config` owns one `tt_config` through `NativeHandle` and `Lease` (wakeup through a `GCHandle` and an `[UnmanagedCallersOnly]` trampoline, as `Terminal.Spawn` does it). `Open` checks the ABI, `TryPoll` copies the sized view into an immutable `ConfigSettings` (no pointers outlive the poll), `Set` writes through `tt_config_set`, `Dispose` frees; non-OK statuses are `ScullException`s. Verify: MSTest `ConfigTests` in `windows/Scull.Core.Tests` against the real library on every runner (defaults and path, a file read at open, `Set` validating and writing while keeping the rest of the file, `Set` refusing bad input with the file untouched, a live edit waking the host and bumping the generation, a broken edit keeping the last good values with an error naming the file, no wakeup after `Dispose`, use after `Dispose`); `just check`, `just windows-core-test`, `dotnet build` with warnings as errors.
  - T20.7.2. Apply font, colours, key bindings and scrollback in `Scull.App` and `Scull.Render` from `Config`, live through the wakeup marshalled to the UI thread (scrollback for new terminals only). Verify: renderer tests on a Windows runner and a run of the app while the file is edited.
    Execution plan: (1) `Scull.Core/ConfigBindings.cs`, plain C#: the configured action for a key (`WindowsKeys.Map`) and the shortcut modifiers held, matched exactly as `TerminalView.runBinding` does; and `FontZoom`, the configured family and size plus the larger/smaller/reset steps clamped to 4–200 and reset when the file changes the font. (2) `Scull.Render`: `Palette` from `ConfigSettings` (foreground, background, cursor and the sixteen ANSI colours over xterm's cube and greys, as `Palette+Config.swift` does); `Renderer.Palette` settable, which rebuilds every row; `Renderer.SetFont` replacing the faces, shaper and atlas while the pipeline stays. A configured family that is not installed falls back to Cascadia Mono, then Consolas. (3) `Scull.App`: `App` opens one `Config` at launch (a failed open keeps the built-in defaults) and exposes it for the settings window (T20.7.3); its wakeup posts to the UI thread's `DispatcherQueue`, which polls and tells every window. A window applies the palette and font to its panes, spawns new terminals with the configured scrollback, matches bindings before keys reach the terminal (paste, font larger/smaller/reset, scroll page/top/bottom) after the pane commands, and shows a config error in an `InfoBar` while the last good settings stay. Edits to `TerminalWindow` and `TerminalPane` stay small (T18.3 works there). (4) Tests: binding matching, font steps and the palette on every runner; on WARP (Windows), a new palette's background and a new font's cell size and glyphs after `SetFont`. Verify: `just check`, `just windows-core-test`, warnings as errors, `just windows-app` on the Windows CI runner.
  - T20.7.3. WinUI settings window (family, size, scheme, scrollback) writing through `Config.Set`. Verify: `just windows-app` on a Windows runner and a screenshot after a change made through the window.
    Execution plan: (1) `Scull.Core/SettingsForm.cs`, pure and tested on every runner: the keys (`font.family`, `font.size`, `colors.scheme`, `scrollback`), the built-in scheme list (macOS `SettingsView.swift`'s: scull-dark, scull-light, solarized-dark), the bounds the core enforces (font size 4 to 200 in steps of 0.5, scrollback 0 to 1,000,000), the validation of typed values into `SettingChange(Key, Value)` with a message for each refusal, and `Write(Config, SettingChange)` that returns the core's message when `Set` throws `Invalid` or `Io`; (2) `Scull.App/SettingsWindow.cs`, code only: an editable font ComboBox (empty is the system monospace), a NumberBox for the size, a ComboBox for the scheme, a NumberBox for scrollback with the note that it applies to terminals opened afterwards, the refusal or the file's own `Error` in red, a Show config file button; it takes a `Config`, shows `Config.Settings`, writes each change through `SettingsForm.Write`, and `Refresh(ConfigSettings)` moves the controls when the App polls (the App owns and polls the `Config`, T20.7.2); (3) the hook: `PaneCommand.OpenSettings` on Ctrl+, and `App.OpenSettings()`, which does nothing until T20.7.2 assigns `App.Config`. Verify: `just check`, `just windows-core-test`, CI `just windows-app`; how it looks needs a human.
    Landed: T20.7.3 `Scull.Core/SettingsForm.cs` (keys, bounds, scheme list, typed-value validation, `Write` that returns the core's refusal), `Scull.App/SettingsWindow.cs` (editable font ComboBox, size and scrollback NumberBoxes, scheme ComboBox, red error line, Show config file; `Refresh(ConfigSettings)`), `PaneCommand.OpenSettings` on Ctrl+, and `App.OpenSettings()` over the `App.Config` T20.7.2 opens (joined at merge: the window is `App.SettingsDialog` and refreshes on `App.ConfigChanged`). Verified on macOS arm64: `just check`, `just windows-core-test` (210 + 34 passed), `Scull.App` compiled with warnings as errors via `-t:Compile -p:WindowsAppSDKSelfContained=false`. Not verified by anyone: the window on screen (layout, editable ComboBox commit on focus loss, NumberBox spin behaviour, Show config file in Explorer), and the hook, which needs T20.7.2. The screenshot the verify line asks for is still to be taken on Windows.

Not verified: a run of the app while the file is edited (needs a Windows desktop); bindings typed on a real keyboard. The default bindings use Super (the Windows key), which Windows keeps for its own shortcuts (Win+V is clipboard history), so on Windows only shift+Page Up and shift+Page Down reach the app until defaults per platform exist; bindings are matched as configured.
- Scrollback note: the grid ring is sized when a terminal is created, so a changed scrollback applies to terminals opened afterwards, not to running ones.
